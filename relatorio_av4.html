02 / 071 · Contexto e visão da solução

Do processo manual ao ecossistema integrado

Na Schulz S.A., os certificados de calibração de instrumentos eram emitidos a partir de planilhas preenchidas manualmente, com cálculo de erro e conferência de tolerância feitos à mão e resultado guardado em arquivos dispersos. O operador no chão de fábrica não tinha como saber, diante do instrumento, se ele estava liberado para uso.

AV1 Investigação do processo manualAV2 Arquitetura serverless de custo zeroAV3 Motor transacional metrológicoAV4 Plataforma, QR Code e nuvem

A AV4 integra o motor de cálculo da AV3 em dois canais publicados na AWS, que compartilham o mesmo backend e a mesma base de certificados:

Plataforma Web GestoraUsada pelos engenheiros da qualidade. Envia a planilha de leituras, calcula os indicadores por ponto, emite o parecer, mantém o histórico, imprime o certificado e gera a etiqueta com QR Code do instrumento.
Aplicativo Mobile de ValidaçãoUsado pelos operadores. Página mobile que abre a câmera do celular, lê o QR Code da etiqueta e mostra na hora se o instrumento está APROVADO ou REPROVADO, com os pontos de ensaio.

Fluxo ponta a ponta

  1. O engenheiro baixa a planilha modelo, preenche as leituras do ensaio e envia pela plataforma, informando instrumento, responsável e chave de acesso.
  2. O Lambda valida o arquivo, calcula média, erro sistemático e classificação de cada ponto e grava o certificado no DynamoDB com uma identificação aleatória de 12 caracteres.
  3. A plataforma exibe o certificado e a etiqueta com QR Code, que é impressa e colada no instrumento.
  4. No chão de fábrica, o operador lê o QR Code com o celular. O código aponta para /c/{id}, então tanto a página de consulta quanto a câmera nativa do celular abrem o resultado.
Regra de negócio central. Um ponto está dentro da tolerância quando |média − valor padrão| ≤ LEA. O certificado só é APROVADO quando todos os pontos estão dentro. A comparação é feita como |soma − padrão × n| ≤ LEA × n com Decimal, sem arredondar médias periódicas.
03 / 072 · Plataforma web e aplicativo mobile

Plataforma Web Gestora

Página única servida pelo próprio Lambda, em HTML, CSS e JavaScript sem framework. Funcionalidades: envio da planilha por arrastar e soltar, download da planilha modelo, resultado por ponto com destaque dos pontos fora do LEA, parecer final, histórico das 50 análises mais recentes, impressão do certificado em PDF pelo navegador e geração da etiqueta com QR Code.

Aplicativo Mobile de Validação (QR Code)

A consulta (/consulta) foi desenhada para celular. O botão principal abre a câmera traseira com a biblioteca html5-qrcode; ao reconhecer o código, a página busca o certificado e mostra o parecer em tela cheia, em verde ou vermelho, com a tabela de pontos. Se a câmera não estiver disponível, o operador digita a identificação. A consulta é pública por desenho: o operador não precisa de login, e a identificação aleatória de 12 caracteres hexadecimais impede a enumeração dos certificados.

A solução atende às duas frentes do roteiro (plataforma web e aplicação mobile) com uma página web responsiva no lugar de um aplicativo nativo: o operador não precisa instalar nada, e a câmera do navegador funciona em HTTPS, que a Function URL já oferece.

04 / 073 · Arquitetura em nuvem

Arquitetura serverless na AWS

Celular / navegador ──HTTPS──▶ Lambda Function URL ──▶ AWS Lambda (Python 3.13, arm64, 256 MB) │ serve as páginas, a API e os cálculos ▼ Amazon DynamoDB (tabela de certificados) CloudWatch Logs (retenção de 7 dias) · AWS Budgets (alerta acima de US$ 0,01)

Toda a infraestrutura está descrita como código em template.yaml (AWS SAM) e é criada por um único script. O mesmo código roda localmente com SQLite (server.py) e na nuvem com DynamoDB (src/lambda_function.py); as rotas ficam em src/web.py e são compartilhadas pelos dois ambientes.

Decisões de projeto para custo zero

Function URL em vez de API GatewayO API Gateway só é gratuito nos 12 primeiros meses. A Function URL não tem cobrança própria além do Lambda e já entrega HTTPS.
Frontend servido pelo LambdaAs páginas são entregues pela própria função, sem bucket S3 público nem CloudFront.
DynamoDB provisionado em 1/1Capacidade fixa e mínima, dentro do limite permanente de 25 unidades, sem risco de cobrança por pico como no modo sob demanda.
Lambda em arm64Graviton consome menos GB-s pelo mesmo trabalho, o que deixa ainda mais folga na cota mensal.
Segurança. O envio de planilhas exige a chave de acesso do engenheiro (cabeçalho X-Chave), guardada em variável de ambiente do Lambda e comparada em tempo constante. O template recebe a chave como parâmetro NoEcho. A função tem permissão apenas de CRUD na própria tabela. Numa versão de produção, a chave iria para o Secrets Manager e o login seria por Amazon Cognito.
05 / 074 · Roteiro de deploy na nuvem

Roteiro de deploy

O deploy é reprodutível e feito por script, a partir de um clone do repositório. Pré-requisitos: conta AWS, Python 3.13, AWS CLI e AWS SAM CLI.

  1. Instalar as ferramentas.
    winget install Amazon.AWSCLI winget install Amazon.SAM-CLI
  2. Criar um usuário IAM para o deploy com permissões de CloudFormation, Lambda, DynamoDB, IAM (criação de papéis), S3, CloudWatch Logs e Budgets, gerar a chave de acesso e configurar a CLI na região de São Paulo:
    aws configure (região: sa-east-1)
  3. Executar o script de deploy, informando o e-mail do alerta de custo e a chave dos engenheiros:
    .\deploy\deploy.ps1 -EmailAlerta email@dominio.com -ChaveAcesso "chave-forte"
    O script confere as credenciais, roda os 14 testes, valida o template, executa sam build e sam deploy e imprime as saídas UrlPlataforma e UrlConsulta.
  4. Confirmar a assinatura do e-mail enviado pelo AWS Budgets para ativar o alerta de custo.
  5. Validar abrindo UrlPlataforma, processando a planilha modelo e lendo o QR Code gerado pelo celular em UrlConsulta.

Atualização e remoção

Novas versões são publicadas rodando o mesmo script, que aplica apenas as diferenças via CloudFormation. Para remover tudo: .\deploy\destroy.ps1. A tabela DynamoDB tem política Retain para não perder certificados numa remoção acidental. Em Linux ou macOS o equivalente é deploy/deploy.sh.

Considerações finais

O projeto saiu de um processo manual e fragmentado para um ecossistema em que o certificado nasce de uma planilha validada, fica registrado na nuvem e chega ao operador por um QR Code colado no próprio instrumento. A arquitetura serverless mantém o custo em zero para o volume da Schulz S.A. e escala sem mudança de código se o uso crescer.

Limitações e próximos passos

O sistema é acadêmico: não calcula incerteza de medição nem substitui a rastreabilidade formal e a assinatura de um laboratório acreditado. Como evolução, propõe-se login com Amazon Cognito, chave no Secrets Manager, validade do certificado com alerta de recalibração e integração com o cadastro de instrumentos da empresa.
